# 0.2.0 adapter release preparation

Status: private release candidate preparation. This source change does not publish packages,
create a tag or GitHub release, deploy an application, or enable reporting.

Both `@bugdrop/browser` and `@bugdrop/server` use version `0.2.0`. The private contracts
workspace remains `0.1.0`; wire contracts and the frozen V2 catalog are unchanged.

## Changes

- Reusable managed Web Request/Response handler at `@bugdrop/server/adapter`.
- Thin raw-stream Node wrapper at `@bugdrop/server/node`, with Vercel configuration guidance.
- Browser anonymous and customer-policy token providers with a matching configurable route.
- Default-off activation, explicit access modes, safe diagnostics, no automatic retries,
  and bounded cancellation across request, policy, exchange and response consumption.

The adapter uses an 18-second total server deadline and a 25-second browser deadline.
Initial support requires Node20+ and the current SDK's Node crypto APIs. Other hosting
platforms can implement the documented translation boundary; edge and hosted-platform
qualification are separate. See [adapter usage](../adapter.md).

## Prepare immutable private artifacts

From clean, committed source, install the locked dependencies and run `npm run validate`.
Then build and pack `@bugdrop/browser` and `@bugdrop/server` with `npm pack --workspace`
into a new private directory. Do not overwrite an existing candidate.

Record the full source commit and tree, package versions, tarball filenames, SHA256 and npm
integrity values, Node/npm versions, and verification results in the candidate manifest.
Consumers pin the exact tarballs with relative `file:` dependencies and a committed lockfile.
Inspect the installed package exports and browser/server boundaries in an isolated consumer.
The manifest must be checked against independently supplied hashes; a manifest beside modified
files alone does not authenticate them.

This private artifact path allows a disabled Foil adoption PR before registry publication.
Preserve Foil's exact origin, route, public/server switches, repository scope and existing key.
Keep the widget URL and all credentials out of release-default guesses and browser secrets.
No app configuration or production authority is created by installing a package.

## Qualification and later publication

Local synthetic SDK tests, packed-export checks and disabled app builds prove local source and
package behavior. They do not establish production issuer acceptance, GitHub delivery, hosted
Vercel raw-byte behavior or fresh-account lifecycle acceptance for this version.

Server `0.2.0` is outside the frozen test-only V2 server catalog and must normalize to `null`.
The existing remote staging safety gate remains pinned to `0.1.0` and must reject this candidate
before any private action. Do not edit either gate to make a new package version appear qualified.
The opt-in exports remain present; this release preparation does not authorize production V2 use.

Before public publication, separately verify package namespace/maintainer authority, final source
review and CI, exact artifact identity and the applicable authoritative-service qualification.
An unauthenticated registry 404 does not distinguish an unpublished package from a private one.
Obtain explicit publication/tag/release approval, then publish only the reviewed artifacts.
Publication, merging a consumer PR, deployment, activation and live reports remain separate steps.
